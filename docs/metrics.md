# 淘宝用户行为分析：指标口径说明

## 1. 数据范围

| 项目 | 定义 |
|---|---|
| 分析表 | `user_behavior` |
| 数据范围 | 2017-11-25 至 2017-12-03 |
| 观察天数 | 9 个自然日 |
| 行为记录数 | 100,095,182 条 |
| 观察期用户数 | 987,991 人 |
| 行为类型 | `pv` / `cart` / `fav` / `buy` |
| 时间口径 | 北京时间 |
| 数据粒度 | 一条记录代表一次用户行为 |

### 数据范围限制

- 数据只覆盖 9 个自然日。
- 可以计算日级行为趋势、日活跃用户和次日留存。
- 7 日留存只能针对拥有完整观察窗口的 cohort 计算。
- 30 日留存无法由当前数据计算。
- 复购周期仅代表 9 天观察窗口内的购买行为间隔。
- 数据没有订单 ID，因此 `buy` 行为记录不等同于订单数。
- 数据没有商品金额字段，因此不能计算完整 RFM 中真实金额意义上的 Monetary 指标。

## 2. 基础指标定义

### 2.1 行为记录数

某类行为在数据表中的记录条数。

```text
行为记录数 = COUNT(*)
```

行为记录数反映行为记录规模，不等于用户数，也不等于订单数。
同一用户可以产生多条相同类型的行为记录。

### 2.2 行为用户数

观察期内至少发生过某类行为的去重用户数。

```text
行为用户数 = COUNT(DISTINCT user_id)
```

例如：

```text
购买用户数
= COUNT(DISTINCT user_id)
WHERE behavior_type = 'buy'
```

不同类型的行为用户可能相互重叠，因此不能将四类行为用户数直接相加。

### 2.3 观察期用户数

观察期内至少发生过一次有效行为的去重用户数。

```text
观察期用户数 = COUNT(DISTINCT user_id)
```

本项目观察期用户数为 987,991 人。

### 2.4 PV

行为类型为 `pv` 的行为记录数。

```text
PV = COUNT(*)
WHERE behavior_type = 'pv'
```

本项目 PV 为 89,660,671 条。

PV 表示浏览行为记录量，不表示浏览用户数。

### 2.5 日活跃用户

某一天内至少发生一次有效行为的去重用户数。

```text
日活跃用户
= COUNT(DISTINCT user_id)
GROUP BY behavior_date
```

本项目中的有效行为包括 `pv`、`cart`、`fav` 和 `buy`。
因此，日活跃用户不等于日浏览用户。

## 3. 四类行为已验证结果

| 行为类型 | 行为记录数 | 行为用户数 | 记录占比 | 用户占比 |
|---|---:|---:|---:|---:|
| pv | 89,660,671 | 984,105 | 89.58% | 99.61% |
| cart | 5,530,446 | 738,996 | 5.53% | 74.80% |
| fav | 2,888,258 | 389,823 | 2.89% | 39.46% |
| buy | 2,015,807 | 672,404 | 2.01% | 68.06% |

四类行为记录数合计为 100,095,182 条，与分析表总记录数一致。

### 3.1 行为记录占比

```text
行为记录占比
= 某类行为记录数 / 全部行为记录数
```

该指标反映行为记录的构成，不是用户转化率。
由于各行分别四舍五入到两位小数，展示值相加可能出现 100.01% 或 99.99%。

### 3.2 行为用户占比

```text
行为用户占比
= 某类行为用户数 / 观察期用户数
```

例如：

```text
购买用户占比
= 672,404 / 987,991
= 68.06%
```

正确解释是：

> 观察期内至少发生过一次购买行为的用户，占观察期用户的 68.06%。

该比例不能直接解释为浏览到购买的转化率。
因为这里没有要求用户先浏览、后购买，也没有建立严格的用户级漏斗阶段。

## 4. 购买相关指标

### 4.1 购买行为记录数

```text
购买行为记录数
= COUNT(*)
WHERE behavior_type = 'buy'
```

本项目购买行为记录数为 2,015,807 条。
该指标不直接等于订单数。

### 4.2 购买用户数

```text
购买用户数
= COUNT(DISTINCT user_id)
WHERE behavior_type = 'buy'
```

本项目购买用户数为 672,404 人。

## 5. 漏斗指标使用原则

本项目不直接使用下面的公式作为严格用户转化率：

```text
buy 记录数 / pv 记录数
```

原因包括：

1. 分子和分母统计的是行为记录，不是同一批去重用户。
2. 该公式没有要求行为发生的时间先后。
3. `fav` 和 `cart` 不一定是所有用户都经过的连续阶段。
4. `buy` 行为记录不等于订单。

后续漏斗分析将优先采用用户级口径，并明确阶段定义、统计对象和分母。

## 6. 留存与复购限制

### 留存

留存分析将根据用户首次出现日期建立 cohort，
再观察用户在后续日期是否再次发生行为。

- 次日留存：可以计算。
- 7 日留存：仅对拥有完整 7 日观察窗口的 cohort 计算。
- 30 日留存：无法计算。

### 复购

由于数据没有订单 ID，复购分析只能基于 `buy` 行为记录进行近似分析。

可以分析：

- 用户产生过几条 `buy` 行为记录；
- 购买行为记录次数分布；
- 观察期内产生两次及以上购买行为记录的用户比例；
- 用户两次 `buy` 行为之间的时间间隔。

不能直接宣称：

- 真实订单复购率；
- 真实订单数量；
- 长期客户生命周期价值；
- 长期意义上的复购周期。

## 7. 指标使用原则

1. 所有指标必须注明统计对象：记录、用户还是订单。
2. 所有转化率必须注明分母。
3. `buy` 行为记录不等于订单数。
4. 购买用户占观察期用户比例不等于浏览到购买转化率。
5. 留存和复购结论必须注明观察窗口限制。
6. Power BI 中展示的指标名称应与本文件保持一致。
